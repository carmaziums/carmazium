**Critical: ArrayBuffer upload pattern** (blob approach breaks on Android — do not use):
```typescript
import * as FileSystem from 'expo-file-system';
import { decode } from 'base64-arraybuffer';
// 1. Read as Base64
const base64 = await FileSystem.readAsStringAsync(localUri, { encoding: FileSystem.EncodingType.Base64 });
// 2. Decode to ArrayBuffer
const arrayBuffer = decode(base64);
// 3. Upload
const { data, error } = await supabase.storage.from(bucket).upload(path, arrayBuffer, { contentType, upsert: true });
// 4. Get public URL (synchronous, no error field)
const { data: urlData } = supabase.storage.from(bucket).getPublicUrl(data.path);
return urlData.publicUrl;
```

**Critical: HEIC conversion** (iOS returns HEIC by default in SDK 54):
- Use `manipulateAsync` (NOT the new class-based API — less stable in SDK 54)
- Loop with 1.2 MB check target (conservative for actual 1.5 MB cap)
- `FileSystem.getInfoAsync(uri, { size: true })` — use `(info as any).size` because the type is narrow

**DVLA auto-trigger rule:** Strip non-alphanumeric from plate input, uppercase it. If cleaned length is 7 or 8 AND `!dvlaFetched` AND `!dvlaLoading`, call `handleDvlaLookup(cleaned)`.

**Zustand persist pitfall:** Only store Supabase public URLs (strings) in images arrays — never local `file://` URIs (ephemeral). Check `useSellWizardStore.persist?.hasHydrated()` before showing "resume draft" prompt.

**File 1: `src/lib/storageHelper.ts`**

Export two functions:

```typescript
export async function convertAndCompress(uri: string): Promise<string>
export async function uploadToStorage(localUri: string, bucket: string, path: string, contentType?: string): Promise<string>
```

`convertAndCompress` implementation:
- Import `* as ImageManipulator from 'expo-image-manipulator'` and `* as FileSystem from 'expo-file-system'`
- Start with `quality = 0.85`, `MAX_BYTES = 1.2 * 1024 * 1024`, `MAX_ITERATIONS = 6`
- Loop up to 6 times: call `ImageManipulator.manipulateAsync(currentUri, [], { compress: quality, format: ImageManipulator.SaveFormat.JPEG })`
- After each iteration call `FileSystem.getInfoAsync(result.uri, { size: true })` and read `(info as any).size ?? 0`
- If `size <= MAX_BYTES` OR iteration is last, return `result.uri`
- Otherwise reduce quality by 0.15 (min 0.3) and continue

`uploadToStorage` implementation:
- Import `* as FileSystem from 'expo-file-system'`, `{ decode } from 'base64-arraybuffer'`, `{ supabase } from './supabase'`
- Read: `const base64 = await FileSystem.readAsStringAsync(localUri, { encoding: FileSystem.EncodingType.Base64 })`
- Decode: `const arrayBuffer = decode(base64)`
- Upload: `const { data, error } = await supabase.storage.from(bucket).upload(path, arrayBuffer, { contentType: contentType ?? 'image/jpeg', upsert: true })`
- If error throw it
- Get URL: `const { data: urlData } = supabase.storage.from(bucket).getPublicUrl(data.path)` — note: getPublicUrl is synchronous with no error field
- Return `urlData.publicUrl`
