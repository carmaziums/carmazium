**Part A — notification-icon.png:**

The `expo-notifications` plugin in `mobile/app.json` already references `"./assets/notification-icon.png"`. The EAS build will fail with an asset-not-found error if this file does not exist.

Create a minimal valid 96x96 PNG at `mobile/assets/notification-icon.png`. Use the Node.js `Buffer` approach to write a minimal valid PNG file programmatically (since no image editor is available):

```bash
cd D:/carmazium/mobile
node -e "
const fs = require('fs');
// Minimal 1x1 transparent PNG (valid PNG header + IHDR + IDAT + IEND)
// Will be scaled by the notification system; designer must replace with 96x96 white-on-transparent brand icon
const png1x1 = Buffer.from(
  '89504e470d0a1a0a0000000d49484452000000010000000108060000001f15c4' +
  '890000000a49444154789c6260000000020001e221bc330000000049454e44ae' +
  '426082',
  'hex'
);
fs.writeFileSync('./assets/notification-icon.png', png1x1);
console.log('notification-icon.png created');
"
```

If the hex decode approach does not produce a valid PNG, use `expo-image-manipulator` or any available Node.js PNG library. The key requirement is that a valid PNG file exists at that path before any EAS build is attempted. Add a TODO comment in the file's parent directory (as a note in this plan) that the designer must replace it with a 96x96 white-shape-on-transparent-background PNG before the production build.
