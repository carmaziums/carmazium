# Staging readiness without a paid Supabase branch — October 2026

This is an **evidence-based preflight plan**, not a claim that a compatible isolated backend has been deployed. The user explicitly disallowed creating a paid Supabase branch; none must be created. The currently available separate CarMazium Development schema was previously found incompatible with current production backend expectations (different auction winner/finance handover columns and analytics event shape). Do not point the pending valuation/security branches at that database or automatically migrate it, and never run Prisma `db push` against production.

## Repository facts verified against production `main`

The checked-in `backend/fly.toml` points to live app **`carmazium-hjoh9w`** in London. It has no release-time schema migration and uses `/health/live` for Fly health checks, deliberately avoiding destructive `prisma db push`. **Do not deploy any draft branch to that production app.**

The existing `backend/Dockerfile` is a two-stage Node Alpine build: builder executes full `npm ci`, Prisma generate and Nest build; runtime executes `npm ci --omit=dev`, and manually copies the builder's Prisma client/CLI and **entire** `node_modules/@prisma` directory into the final image. It defaults to **Node 20.10.0**, while the currently resolved `@nestjs/cli@11.0.24` declares Node `>=20.11`. Passing GitHub-hosted TypeScript/Jest on Node 20.20 is not proof the default Fly Docker build works. A future isolated Docker test must build with a supported, verified Node 20 patch tag before any Dockerfile version change.

The legacy backend manifest had `@nestjs/cli` and `@nestjs/schematics` in production dependencies; a clean `npm ci --omit=dev` did include `@swc/cli` and vulnerable download/archive transitive modules. The draft targeted correction in security PR **#377** reclassifies these as build-only and requires actual production-install proof. Do not accept a dependency scanner's `--omit=dev` flag alone as evidence that a physical production image is free of build-only packages, especially while the Dockerfile copies modules directly from builder.
